# 11 · REST Client y microservicios Books/Authors

Proyectos: [`app-books`](../code/prog-distribuida/app-books) (puerto 8080) y [`app-authors`](../code/prog-distribuida/app-authors) (puerto 8070). Base Quarkus: [nota 10](10-2026-11-09-quarkus.md); anotaciones REST: [nota 08](08-2026-11-05-jakarta-rest-servidores.md).

## Consumir microservicios
- `app-books` no tiene los autores: los obtiene de `app-authors` por HTTP.
- Cada servicio tiene su propia responsabilidad y su propio modelo (database per service).
- **MicroProfile REST Client**: cliente HTTP tipado, declarado como **interfaz** con anotaciones JAX-RS; el runtime genera la implementación.

| Aspecto | Detalle |
|---|---|
| Registro | `@RegisterRestClient(configKey = "authors")` |
| URL | `quarkus.rest-client.authors.url=http://localhost:8070` |
| Inyección | `@Inject @RestClient AuthorRestClient` |
| Dependencias | `quarkus-rest-client`, `quarkus-rest-client-jsonb` |

```java
@RegisterRestClient(configKey = "authors")
@Path("/authors")
public interface AuthorRestClient {
    @GET @Path("/find/{isbn}")
    List<AuthorDto> findByBook(@PathParam("isbn") String isbn);
}
```

- `@PathParam` si el valor va en la ruta (`/find/{isbn}`); `@QueryParam` solo para `?isbn=...`.
- La URL nunca va en el código: se externaliza (config) para cambiarla por entorno.

## Capas en `app-books`

| Paquete | Rol |
|---|---|
| `db` | Entidades JPA (`Book`, `Inventory`) |
| `repo` | Panache Repository (`PanacheRepositoryBase<Book, String>`) |
| `services` | Lógica: interfaz + `impl`, mapeo entidad → DTO |
| `dtos` | `BookDto`, `AuthorDto` (contrato expuesto) |
| `clients` | REST Client hacia otros servicios |
| `rest` | Recursos JAX-RS |

- **DTO**: no se expone la entidad; `BookDto` combina datos de `Book`, `Inventory` y la lista de autores remotos.
- Inyección por **constructor** (`@Inject` en el constructor, campos `final`).
- `@Transactional` en repositorio/servicio.

## JPA en Quarkus

| Concepto | Uso |
|---|---|
| `quarkus-hibernate-orm-panache` | Repository: `listAll`, `findByIdOptional`, `find(query, params)` |
| `quarkus-jdbc-postgresql` | Driver; `quarkus.datasource.*` |
| `@OneToOne(mappedBy)` | Lado inverso `Book` → `Inventory` |
| `@Id @OneToOne @JoinColumn` | PK derivada: la PK de `Inventory` es la FK a `Book` |
| `@EmbeddedId` + `@Embeddable` | PK compuesta (`BookAuthorId`) |
| `@MapsId` | La FK de la relación forma parte de la PK embebida |
| `@JsonbTransient` | Evita ciclos al serializar la relación bidireccional |

- Consulta JPQL: `select o.author from BookAuthor o where o.id.booksIsbn = ?1`.
- Tabla intermedia `books_authors` (N:M libros–autores).

## MicroProfile Config
- Fuentes por **ordinal** (mayor prioridad gana): propiedades de sistema `-D` (400) > variables de entorno (300) > `application.properties` (250) > `microprofile-config.properties` (100).
- Acceso: `ConfigProvider.getConfig().getValue(...)`, `getOptionalValue(...)` o `@ConfigProperty(name, defaultValue)`.
- En Quarkus `@Inject` es opcional con `@ConfigProperty`.
- Sobrescribir: `java -Dquarkus.http.port=8070 -jar build/quarkus-app/quarkus-run.jar`.
- Cada servicio en un puerto distinto (`quarkus.http.port`) para correr juntos.
